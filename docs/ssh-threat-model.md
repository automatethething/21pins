# Temporary SSH V1 threat model

## Boundaries and assumptions

21pins authenticates its requester and signs a public key; native SSH transports traffic directly to an ordinary sshd. The CA/issuer host, its administrator-controlled configuration, requester authentication, clock and target OS/principals configuration must be trusted. A role is an OS-account/SSH-feature authorization, **not** command-level sandboxing or protection from an authorized shell.

Existing app-token identity is reused, but only exact `ssh:use`/`ssh:approve` permissions authorize SSH. Proxy wildcards never imply SSH. Duplicate active token names and auth-state reload errors fail closed. The CA signing socket is separate from all client subprocess environments. Files use private ownership/mode, non-symlink access and atomic replacement; metadata writes/serial reservation are serialized across processes. Same-UID administrator compromise is outside file-permission isolation; no local enclave claim is made.

## Threats and mitigations

- **Ephemeral credential theft.** A private key alone cannot authenticate without its issued certificate. Key+certificate can authenticate only to correctly configured host/role accounts until short expiry. Normally the client unlinks both on completion/cancellation. No physical secure-erase claim for SSDs, snapshots or backups.
- **Requester credential theft.** An authenticated requester can only use already configured host/role permissions. A preapproved role permits opening new key-bound leases within its policy ceiling; explicit-approval roles still need a distinct administrator. A credential plus the original lease private key can renew until lease/policy/credential revocation or hard expiry. Short certificates alone do not cure a stolen renewal credential. Revoke the app credential and affected leases, secure the endpoint, and observe the existing certificate residual window.
- **Approval credential theft.** This is high authority, not an agent credential. Keep it owner-only, outside harness/model environment. Approvals are exact immutable lease records and cannot self-approve. Review host/role/objective/purpose/deadline before approval; higher privilege must remain explicitly approved.
- **Compromised CA:** can mint credentials for any trusted principal/role, including outside the normal control-plane policy. Production signing uses owner-managed native-agent custody, never private material in application state or API/logs. Compromise of the signer host/socket is a signing-authority compromise even when private bytes cannot be exported. Remove old host trust, rotate CA, inspect affected audit metadata and restore a known-good issuer. Existing sessions are not automatically killed.
- **Compromised target:** target can read/alter data and circumvent its own OS access policy. There is no protection for traffic after a compromised target terminates SSH, no target-side attestation and no data isolation from a root-compromised machine. No CA private material is installed there.
- **Cross-host/role replay:** certificates carry exactly `21pins:<workspace>:<host>:<role>` and a dedicated Unix-account mapping. Target users' root-owned principal files accept only that host's roles. Wrong host/role/user tests must fail. Shared CA alone is insufficient authorization. Misconfigured duplicate host IDs/principal lists can defeat this property; never reuse host identities on another physical target.
- **Privilege creep:** only the same key/fingerprint/requester can renew; all scope derives from the lease. Host alias, role/login, role limits/features, requester mapping, workspace and CA fingerprint are digested. Changed configuration blocks renewal. Hard expiry is fixed; no silent extension. Estimates and model consensus grant no authority.
- **Stale lease after crash:** no detached renewal service is started. Existing certificate expires and the hard lease deadline blocks new issuance. Client startup/status sweeps remove terminal/expired material; a SIGKILL can leave private cache files until a later sweep. An unconfirmed server closure retains metadata-only retry intent, blocks local reuse and deletes local credentials; Pi retries closure on restoration. During control-plane outages, local cleanup is not confirmed server termination: renewal authority ends at confirmed closure or the hard lease deadline. File secrecy and short certificates—not guaranteed crash-time deletion—are the boundary. Existing sessions/detached jobs can survive independently.
- **Active session after expiry/completion:** OpenSSH validates at authentication time. No daemon/proxy/KRL callback means no instantaneous hard termination. Harness best-effort closes its owned local SSH process group on terminal status/signal, but a copied credential or other session may remain until logout, and background remote work may continue. Prefer one-shot commands, disable connection multiplexing, keep certificate TTL short. Hard host-side termination is explicitly out of scope.
- **Malicious agent asks for a broader role/host:** policy selects exact requester/host/role. Inputs never set authenticated actor or grant reviewer rights. Unknown JSON fields/private keys/certificates/options are rejected. Root must require explicit approval. Purpose strings reject controls/bidi formatting to avoid approval-display spoofing; estimates do not decide authorization.
- **Log leakage:** signing subprocess output/errors are not passed through; API errors are generic, bodies bounded, no native debug logs or key contents enter audit. Backend records serial/validity/fingerprint only; certificate response and client certificate cache are functional credential delivery, not audit storage. Terminal output belongs to the invoking harness, never 21pins API/receipt storage.
- **Connection/config leakage:** client resolves a local alias, constructs clean direct SSH arguments and does not inherit proxies, agent sockets, local commands or arbitrary flags. Always normal known-host verification, IdentityAgent none, no ControlMaster/Persist. Logical host metadata replaces stored addresses. Loopback TCP is not sufficient isolation by itself; strong scoped authentication and browser rejection remain required. Unix-domain transport is future hardening, not a promised V1 feature.
- **Signing races/state loss:** reserve a unique serial under bounded cross-process locking before native signing; failed signing/record persistence returns no credential and never reuses the reserved serial. Cryptographically verify native certificate signature, CA, public key, principal, serial, validity and exact extension allowlist before delivery. Back up the serial high-water mark with issuer configuration; rotate after state loss rather than resume a reset counter under the same CA.

## CA rotation/recovery runbook

No automatic rotation is shipped in V1. Public key reference/fingerprint and workspace-scoped signer selection are explicit extension points, not a universal global CA.

1. Stop new issuance/renewal and close/revoke affected leases.
2. Generate/load a new workspace CA in owner-approved secure custody. Never paste/export its private key into chat or ordinary application state.
3. Review and install new public trust/principals on a non-production target first, with sshd validation, safe reload and rollback.
4. Update the issuer's pinned public fingerprint/reference. Existing leases' digests no longer match; open newly authorized leases with fresh client keys.
5. For routine rotation, overlapping public trust is an explicit owner decision until old certificates expire. For compromise, remove old trust immediately; any delay preserves the compromised CA's authority.
6. Remove old agent signing authority, verify new logins and old-certificate denial on fresh connections. Do not claim already-open connections were killed by this.

## Review and verification

Claude independent architecture/security review approved after exact SSH permission isolation, workspace/host/role principals, separate CA socket/client environment and honest residual windows were specified. agy reviewed the implementation/testing strategy; final post-implementation advisory review is recorded in the implementation report. Advisors receive only abstract minimized descriptions, never repo dumps, CA keys or infrastructure configuration. Their agreement grants no new production authority.

Automated checks include lease transitions/limits/approval, immutable renewal, cross-identity rejection, raw public-key validation, secret-free metadata, symlink rejection, concurrent serials and failed-signing reservation, native option/signature validation, production native-agent custody, API permission/origin/private-field rejection and actual harness terminal hooks. Isolated real OpenSSH tests verify the physical authentication properties and deliberately verify the non-property of hard session termination.
